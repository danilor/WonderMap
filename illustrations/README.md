# WonderMap illustrations

Everything you *see* on a WonderMap map is generated by code in this folder: terrain textures,
symbols (mountains, trees, castles, ships, sea serpents…), path styles, label styles, frames and
map themes. **No image files.** The app imports this package as `@wondermap/illustrations`; nothing
in `client/` or `server/` knows how any single illustration is drawn.

Adding or changing art therefore never requires touching app code: drop a file in the right folder,
open the gallery (`http://localhost:5173/#/gallery`) and it is already there. It also shows up in the
editor's library automatically. Finish with `npm run assets`, which redraws the picture catalog
[ASSETS.md](../ASSETS.md) (see [Look at your work](#look-at-your-work)).

## Folder map

| Folder / file | What lives there | Default export of each file |
| --- | --- | --- |
| `symbols/<category>/*.ts` | Stamps placed on the map (one file can hold many) | `SymbolDef` or `SymbolDef[]` |
| `brushes/*.ts` | Scatter presets that paint many symbols while dragging (forest, hills…) | `BrushDef` or `BrushDef[]` |
| `terrain/*.ts` | Paintable ground textures (grass, desert, ice…) | `TerrainDef` |
| `paths/*.ts` | Line styles (river, road, trail, border…) | `PathStyleDef` |
| `labels/*.ts` | Label presets (font, size, spacing, halo) | `LabelStyleDef[]` |
| `themes/*.ts` | Whole-map looks (sea colors, coast, paper, color grade) | `MapTheme` |
| `frames/*.ts` | Decorative map borders | `FrameDef` |
| `fonts/index.ts` | Fonts the labels can use (loaded from `@fontsource`) | – |
| `categories.ts` | Library categories (id, name, icon, order) | – |
| `parts/*.ts` | Shared drawing parts reused by many symbols (`drawPeak`, `drawRoundTree`, `drawHouse`…) | – (helpers) |
| `kit/*.ts` | The drawing toolkit: rng, noise, colors, shapes, draw helpers, textures | – (helpers) |
| `catalog.ts` | Auto-discovers and validates everything above. **Do not edit to add art.** | – |
| `tests/` | Smoke tests that draw every symbol with a fake canvas | – |

`catalog.ts` uses Vite's `import.meta.glob`, so files are found by folder. A file without a default
export is treated as a helper and ignored (that is why `parts/` is outside the globbed folders).

## The rules (read once)

1. **Design box.** A symbol draws in `[0, w] × [0, h]` (y grows downward). `size` is that box in map
   pixels at scale 1. Selection, bounds and the stamp footprint use the box, so keep the art inside it.
   The rasterizer tolerates a small overdraw margin (`overdraw()` in `kit/bounds.ts`, 8% of the larger
   side, at least 6 px) so soft shadows and rough edges are not cut flat. Anything beyond that margin is
   clipped; `npm run check:art` finds it (see [Look at your work](#look-at-your-work)).
2. **Light comes from the top-left.** Lit faces look left/up, shaded faces right/down. Shadows fall to
   the lower right. Every symbol follows this so mixed scenes look coherent.
3. **Ink outline.** Use a dark warm ink (`#2a2015` family) for outlines, 1–2.4 px.
   Coloured shapes get an ink pass first and a fill pass second so the outline stays clean.
4. **Randomness only through `rand`.** `rand` is seeded from the symbol id and variant, so a symbol
   always looks identical across sessions, exports and machines. Never use `Math.random()` or `Date`.
5. **Ids are forever.** Saved maps reference symbols and terrains by id. Never rename or reuse a
   published id; add a new one instead. Use `family.variant` ids (`tree.oak`, `mountain.snowy`).
   Duplicate ids throw at import time and break the whole catalog, so the gallery tells you immediately.
6. **Anchor = where it touches the ground.** `anchor` (normalized) is the contact point used for
   placement and depth sorting. Default `[0.5, 0.92]`.
7. **Variants.** `variants` is the number of distinct looks (default 6). Each variant is rendered once and
   cached; keep it small for big sprites.
8. **Reuse parts.** Put anything used by two or more symbols in `parts/` (see `parts/tree.ts`,
   `parts/peak.ts`, `parts/building.ts`). Symbols should be small recipes that combine parts.
9. **Stay cheap.** A sprite is drawn once per (id, variant, scale) and cached, but draw functions still
   run on the main thread; avoid thousands of strokes per symbol.
10. **Theme-aware by grading, not by branching.** The sprite cache applies the theme's color grade; don't
    read the theme inside a symbol.

## Add a symbol: worked example, the Sea Serpent

The real file is [`symbols/sea/sea-serpent.ts`](symbols/sea/sea-serpent.ts). The shape of any symbol is:

```ts
import { defineSymbol } from '../../kit/define';
import { shape, shades } from '../../kit/draw';

export default defineSymbol({
  id: 'serpent.sea',            // unique + permanent
  name: 'Sea Serpent',          // shown in the library
  category: 'sea',              // must exist in categories.ts
  size: [200, 96],              // design box in map px
  anchor: [0.5, 0.82],          // waterline
  placement: 'sea',             // hint for the UI
  rotatable: true,              // enables the rotation handle
  variants: 4,
  tags: ['monster', 'dragon'],  // search keywords
  draw({ ctx, w, h, rand }) {
    // …paint with ctx inside [0,w] x [0,h], using rand for every random decision
  },
});
```

To add your own creature, copy the file, change `id`/`name`, and edit `draw`. Save the file and open
`#/gallery?category=sea&zoom=2&bg=sea`. With `npm run dev` running, Vite picks up new and edited art
files, and the page **reloads itself** after each save: the catalog is imported by the editor store, whose
hot-reload guard (bottom of `client/src/store/editorStore.ts`) prefers a clean reload over a half-updated
store. Reload time is short, and the gallery keeps its settings in the URL, so you stay on the same view.

A file can export an array to define several symbols from one factory (see `symbols/mountains/peaks.ts`:
`single(...)` and `range(...)` produce 11 symbols).

### Helpers worth knowing (all exported from `kit/`)

| Need | Use |
| --- | --- |
| Filled/stroked polygon, optionally smoothed | `shape(ctx, pts, { fill, stroke, width, closed, smooth, alpha })` |
| Ellipse, dot, rect, polyline, tapered stroke | `ellipse`, `dot`, `rect`, `line`, `taper` |
| Gradients | `linearGradient`, `radialGradient` |
| Light/dark variants of one color | `shades(base)` → `{ highlight, light, base, shade, deep }` |
| Color math | `mix`, `lighten`, `darken`, `rgba`, `adjust`, `hsl` |
| Soft ground shadow / blob | `groundShadow`, `softBlob` |
| Clip drawing to a polygon | `clipped(ctx, poly, () => …)` |
| Hand-drawn strokes | `hatch`, `stipple` |
| Organic outlines | `blob`, `jagged`, `wobble`, `catmullRom`, `chaikin`, `ribbon`, `normals`, `resample` |
| Randomness | `rand.range/int/chance/pick/gauss/fork(salt)` |
| Noise | `valueNoise`, `fbm`, `tileNoise`, `tileFbm` |
| Seamless texture strokes (terrain) | `noiseTile`, `blotches`, `speckles`, `ticks`, `waves`, `wrapped` |

## Add a scatter brush

Brushes make dragging paint a whole forest or mountain range. They reference symbol ids and are
validated at import: a missing id throws, so add the symbols first.

```ts
import { defineBrush } from '../kit/define';

export default defineBrush({
  id: 'brush.forest.oak',
  name: 'Oak forest',
  category: 'forests',
  items: [{ symbol: 'tree.oak', weight: 3 }, { symbol: 'tree.oak.dark', weight: 1 }],
  spacing: 26,          // map px between stamps
  scale: [0.8, 1.2],
  jitter: 0.45,
});
```

## Add a terrain

Create `terrain/<id>.ts` with `defineTerrain({ id, name, swatch, order, colors, texture(t) {…} })`.
`texture` paints ONE seamless tile into `[0, size]²`; use the helpers in `kit/texture.ts` (they wrap
around the tile edges). Terrain indices are runtime-only (sorted by `order`), maps store the `id`.

## Add a category, path style, label style, theme, frame or font

* **Category**: add an entry to `categories.ts` (`icon` is a Bootstrap-Icons name without `bi-`).
* **Path style**: `paths/<id>.ts` with `definePathStyle`; `draw` receives the smoothed polyline and a width per point.
* **Label style**: append to `labels/styles.ts` (font id, size, spacing, halo).
* **Theme**: `themes/<id>.ts` with `defineTheme`; the frame must exist in `frames/`.
* **Frame**: `frames/<id>.ts` with `defineFrame`; `inset` reserves the border width.
* **Font**: install it into this package (`npm i -w illustrations @fontsource/<name>`), import the weights you
  need at the top of `fonts/index.ts`, and register it there with `defineFont` (id, display name, CSS family,
  weights, styles). Give a label style that font id. `ensureFonts()` loads the faces before labels are drawn
  and before an export, so nothing else has to change. Keep to open licenses (OFL).

## Look at your work

```bash
npm run dev                       # API on :4000 and client on http://localhost:5173
npm run dev -w client             # the gallery only needs the client
# gallery URL parameters
#/gallery?tab=symbols|terrain|frames|labels&category=<id>&q=<search>&theme=<id>&zoom=1|2|3&bg=none|grass|earth|sand|snow|swamp|stone|sea|paper&variants=6&debug=1
npm run shot -- "http://localhost:5173/#/gallery?category=sea&zoom=2&bg=sea" out.png --size 1500x700
```

`debug=1` draws the design box and the anchor point, which is the fastest way to verify that
nothing leaks outside the box and that the anchor sits on the ground.

Three helpers drive a real browser (Edge or Chrome, through `playwright-core`; no download needed):

```bash
# 1. Screenshot any page: npm run shot -- <url> <out.png> [--size 1600x1000] [--wait 800] [--selector "#id"] [--dpr 1]
npm run shot -- "http://localhost:5173/#/gallery?category=sea&zoom=2&bg=sea" out.png --size 1500x700

# 2. Find art that spills beyond the overdraw margin (needs the dev server on :5173)
npm run check:art                           # every symbol and variant
npm run check:art -- --filter serpent.      # only symbol ids that start with this text
npm run check:art -- --all                  # also list harmless spills that stay inside the margin

# 3. Redraw the picture catalog ASSETS.md (starts its own Vite server; about 20 s)
npm run assets                              # everything, and removes the pictures of assets that are gone
npm run assets -- --only symbol,brush       # just these kinds: terrain symbol brush path label font theme frame
npm run assets -- --filter serpent          # just the assets whose id contains this text
```

### Keep ASSETS.md current

[ASSETS.md](../ASSETS.md) shows a picture of every asset, drawn with the app's own engine into
`docs/assets/`. After **any** change to the art (a new or edited symbol, brush, terrain, path, label
style, font, theme or frame), run `npm run assets` and commit `ASSETS.md` and `docs/assets/` together
with the change. A unit test compares them with the art and fails with a message that tells you to
run it, so a stale catalog cannot be committed by accident (`npm test`).

The partial runs (`--only`, `--filter`) are for looking at a few pictures while you work: they never
rewrite `ASSETS.md`, so finish with a full `npm run assets` before you commit.

## Quality bar

* Reads clearly at 40–120 px, which is how it appears on a map; avoid detail that only works at 4×.
* Looks hand-drawn: slightly irregular edges, two or three tone shading, and a confident ink line.
* Variants differ visibly (silhouette and proportions), not just in hue.
* Always check the symbol on the background it is meant for (`bg=sea` for sea creatures, `bg=grass` for land).
